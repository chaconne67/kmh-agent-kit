# R&D 증빙 DOCX 작성

세액공제를 받으려면 연구가 실제로 있었다는 기록이 남아 있어야 한다. 이 스킬은 고객 원천자료와
검증 가능한 리서치를 바탕으로 연구개발계획서·연구노트·연구일지·업무일지·비용 및 증빙 문서를
회사별 DOCX로 만든다. 산출물은 과세당국과 KOITA가 읽는 문서이므로 지어낸 사실을 넣으면
가산세와 인정 취소로 돌아온다.

## 실행 위치

- 실행·자료관리의 정본은 메인서버(DB)의 `/home/chaconne/projects/rndlog/`다.
- 회사별 작업 공간은 `/home/chaconne/projects/rndlog/자료/<정식 회사명>/`이다.
- 운영서버 `rndlog`의 `/home/chaconne/rndlog`는 웹서비스 코드와 런타임만 운영한다. 고객 원본,
  리서치, 보고서 작업본과 DOCX 산출물을 생성하거나 정본으로 보관하지 않는다.
- 스킬 정본은 메인서버 `/home/chaconne/kmh-agent-kit/skills/domains/rndlog/rndlog/SKILL.md`이며
  GitHub `chaconne67/kmh-agent-kit`의 도메인 스킬 구조로 관리한다.
- 시작 전에 메인 프로젝트의 `AGENTS.md`, `README.md`, 회사별 `README.md`와 자료 현황을 확인한다.

## 고객 자료 수집

1. 고객 원천자료는 카카오톡에서 Windows PC로 내려받는다.
2. 채팅방 이름이 아니라 사업자등록증의 정식 법인명으로 회사를 식별한다.
3. 메인서버 `자료/<정식 회사명>/inputs/`에 받은 파일을 원본 그대로 올린다.
4. 회사 폴더가 없으면 `inputs/`, `research/`, `reports/source/`, `reports/output/`과 `README.md`를 만든다.
5. 원본 파일은 수정·덮어쓰기·자의적 이름 변경을 하지 않는다. 같은 이름의 새 파일은 입수일이나
   버전을 구분해 둘 다 보존한다.

필수 원본이나 확정값이 없으면 생성 단계로 넘어가지 않는다. 빠진 항목과 필요한 제공자를
구체적으로 보고하고, 확인되지 않은 사실이나 수치로 빈칸을 채우지 않는다.

## 진행 순서

여섯 단계를 순서대로 밟는다. 앞 단계의 산출물이 다음 단계의 입력이므로 건너뛰지 않는다.

### 1. 회사 정보 취합

- 입력: `자료/<정식 회사명>/inputs/`에 받은 원본 — 인정서, 사업자등록증, 회사소개서,
  연구개발개요서, 특허·인증 서류.
- 홈페이지도 함께 조사한다. 제품·서비스·조직·채용공고가 연구 인력과 과제의 근거가 된다.
  현재 내용과 출처 URL을 함께 기록한다.
- 결과는 `자료/<정식 회사명>/README.md`에 표로 적는다. 최소 항목: 법인명·사업자번호·대표자·
  소재지·사업 내용, 인정 구분과 인정번호·인정일, 연구원 명단과 투입률·연봉, 특허 목록.
- **인정번호와 인정일은 반드시 인정서 원본에서 읽는다.** 이 값이 틀리면 문서 전체가 무효다.

### 2. 연구 유망 기술 선정

회사가 이미 가진 것에서 출발해야 과제가 사후에 부정되지 않는다. 특허·제품·인력과 무관한
주제는 아무리 유망해도 고르지 않는다.

조사할 것:

- 국내외 논문 — 과제의 기술적 근거가 된다. 과제 착수 시점에 최신이라고 말할 수 있는 것을 고른다.
- 산업 동향·시장 규모 — 연구개발계획서의 「연구 배경 및 필요성」에서 출처와 함께 인용한다.
- 선진업체 사례 — 「기존 기술 대비 차별성」의 비교 대상으로 사용한다.

결과는 `자료/<정식 회사명>/research/`에 남긴다. 주제는 3~5개를 제안하고 그중 하나를 고른다.
법령·세액공제·KOITA 요건은 저장된 과거 문서만 믿지 말고 현재 공식 자료로 확인한다.

### 3. 기술 자료 취합

고른 주제의 근거 자료를 모은다. 논문은 제목·저자·학술지·연도까지 적고, 시장·제도 자료는
발행기관·문서명·발행일·URL·확인일을 기록한다. 출처 없는 수치는 문서에 넣지 않는다.

### 4. 증빙 풀세트 생성

| 문서 | 주기 | 조건 |
|---|---|---|
| 연구개발계획서 | 연 1회 | 항상 |
| 연구노트·연구일지 | 주 1회 | 항상 |
| 업무일지 | 주 1회 | 항상 |
| 인건비배분표 | 분기 | 항상 |
| 연구과제총괄표 | 연 1회 | 항상 |
| 인력개발비명세서 | 연 1회 | 항상 |
| 완료보고서 | 과제 종료 시 | 항상 |
| 회의록 | 분기 | 연구원 2명 이상 |
| 자가점검보고서 | 분기 | 1인 전담부서 — 회의록을 갈음 |

- **최종 문서 형식은 DOCX다.** HTML이나 PDF를 신규 최종 산출물로 만들지 않는다.
- 파일명: `<연도>_W<주차 2자리>[_<주제>].docx`(주간), `<연도>_Q<분기>.docx`(분기),
  `<연도>.docx`(연간). 주차는 ISO 기준으로 센다.
- 편집 작업본: `자료/<정식 회사명>/reports/source/<카테고리>/`
- 검토 완료본: `자료/<정식 회사명>/reports/output/<카테고리>/`
- 진행 중인 회사는 기존 문서 주기와 파일명을 이어가되, 신규 산출물은 DOCX로 만든다.

문서에 반드시 들어가야 하는 것:

1. **기술적 불확실성** — 착수 시점에 무엇을 몰랐는지 적는다.
2. **기존 기술 대비 차별성** — 단순 도입·구매·외주가 아니라는 근거를 적는다.
3. **시행착오 기록** — 실패한 시도와 판단 변경을 연구노트에 남긴다.

시나리오로 채운 정량 수치가 있다면 회사 README와 문서에 **실측 아님**을 명시하고, 실제 제출
전 반드시 회사가 실측값으로 확인·갱신하도록 표시한다.

### 5. DOCX 보고서 스타일

스타일 참조 정본:

```text
/home/chaconne/projects/rndlog/공통/양식/design-report-reference.docx
```

이 파일은 RNDLOG와 무관한 일반 Design Report 샘플이다. **내용 템플릿이 아니라 디자인 스타일만
참조한다.** 원본 파일은 변경하지 않는다.

적용할 것:

- A4 페이지 설정과 안정적인 여백
- 제목·부제·작성일의 명확한 위계
- 절제된 흑백·회색 중심의 본문
- 일관된 Heading 1/2/3, 본문, 캡션, 목록 스타일
- 얇은 선과 최소한의 음영을 쓴 단순한 표
- 페이지 번호, 머리말·꼬리말, 목차 등 일반 보고서 요소
- 충분한 여백과 읽기 쉬운 문단 간격

사용하지 않을 것:

- 샘플의 영문 문구, 목차 항목과 보고서 내용
- 샘플 표지의 사진이나 다른 프로젝트 이미지
- RNDLOG 로고·견적서 색상·웹 UI 디자인 시스템
- 과도한 색상, 카드형 장식, 인포그래픽, 마케팅 문서 표현
- 단순 연구보고서에 필요하지 않은 장식 요소

문서 생성은 사용 가능한 DOCX 도구 또는 `python-docx`로 참조 파일을 복제·가져와 스타일 체계를
유지하는 방식으로 한다. 원본 OOXML에 직접 문자열 치환하지 않는다. 보고서 종류마다 사실에 맞는
구성을 사용하며, 샘플의 영문 섹션을 억지로 채우지 않는다.

### 6. DOCX 검증과 확정

1. 작업본을 `reports/source/`에 생성한다.
2. 본문·표·머리말·꼬리말을 다시 읽어 원천자료와 대조한다.
3. DOCX ZIP 패키지와 관계 파일이 정상인지 검사한다.
4. 남은 샘플 문구, 영문 placeholder, 깨진 스타일·표·번호·빈 페이지가 없는지 확인한다.
5. 가능하면 Word 또는 LibreOffice로 렌더링해 페이지 단위로 육안 검토한다.
6. 검토가 끝난 DOCX만 `reports/output/`에 둔다.

PDF 변환은 사용자가 별도로 요청한 경우에만 DOCX의 보조 사본으로 수행한다. PDF를 원본이나
최종 정본으로 취급하지 않는다.

## 레거시 HTML/PDF

기존 HTML·PDF 문서는 과거 산출 이력으로 보존할 수 있지만 신규 문서의 템플릿이나 최종 경로로
사용하지 않는다. 레거시 자료를 신규 DOCX로 바꿀 때는 내용을 원천자료와 다시 대조하며, 이미
제출한 문서를 소급해서 바꾸지 않는다.

## 마무리

- 회사 README의 산출 이력에 작성일·문서명·DOCX 위치·검토 상태를 추가한다.
- 새로 알아낸 제도 규정은 `공통/기준자료/기업부설연구소관리.md`에 반영한다.
- DOCX 작업본은 `reports/source/`, 검토 완료본은 `reports/output/`에 둔다.
- 자료와 산출물은 메인서버에만 남기고 운영서버로 복사하지 않는다.

## 금지

- `inputs/`의 회사 제공 원본을 고치지 않는다.
- 출처 없는 수치·논문·기관명·연구원·실험 결과를 넣지 않는다.
- 다른 회사나 Design Report 샘플의 문구·사진·내용을 복사하지 않는다.
- HTML→PDF·WeasyPrint를 신규 문서의 공식 생성 경로로 사용하지 않는다.
- 이미 제출한 문서를 새 규칙에 맞춰 덮어쓰지 않는다.
