# Agent API And Exdigm Access

## Boundary

Hermes가 사용자의 자연어를 해석하고 가용한 도구를 자율적으로 조합한다.

- Django는 agent key로 현재 사용자를 찾는다.
- Django는 현재 웹 사용자와 같은 권한을 적용한다.
- 성공과 실패는 `AgentAuditLog`에 기록한다.
- 사용자·역할·권한은 Hermes 요청에서 받지 않는다.

## Negative Control

- 기본적으로 Hermes의 탐색과 도구 사용을 허용한다.
- 인증 우회, 권한 초과, 다른 직원·환경 접근을 차단한다.
- 비밀번호, token, API key, 세션과 시스템 비밀값을 차단한다.
- 데이터 삭제와 삭제에 준하는 제거를 차단한다.
- 시스템 파일·서비스·배포 상태 훼손과 권한 상승을 차단한다.

업무 시나리오, 모델, 필드와 함수를 허용 목록으로 열거하지 않는다. 오류 사례마다
JSON 문법·변환기·보정 단계를 추가하지 않는다.

## Navigation

안내 지도는 관련 파일·데이터·서비스를 빨리 찾기 위한 작은 힌트다.

- 전체 모델·필드·함수 설명을 한 번에 반환하지 않는다.
- 지도에 없는 대상이라는 이유로 접근을 거부하지 않는다.
- 지도는 권한이나 실행 계약의 정본이 아니다.

## Current Transition State

현재 코드는 `exdigm_map`과 `exdigm_execute`를 노출한다. 이 두 도구는 배포 중인
전환 상태의 운영 표면이며 목표 접근 설계의 정본이 아니다.

- 새 제한 문법이나 업무별 전용 도구를 추가하지 않는다.
- 파일·코드·DB 접근의 격리 방식은 후속 grill-with-docs에서 결정한다.
- 새 구조가 승인되기 전에는 현재 경로의 결함 수정과 운영 보존만 수행한다.

## Pagination

- 응답은 `total`, `returned`, `has_more`, `next`를 항상 구분한다.
- 제한은 응답 한 번의 크기이지 전체 일치 건수의 제한이 아니다.
- `has_more=true`면 현재 페이지를 요약하고 전체 수를 밝힌다.
- 사용자가 나머지를 계속 볼지 묻는다.

## Privacy And Email

- 후보자 연락처·이력서·이메일은 헤드헌팅 업무의 정상 데이터다.
- 별도 일반론으로 숨기지 않고 현재 웹 권한을 그대로 적용한다.
- 이메일 읽기·쓰기는 Django와 Mailplug 연동이 소유한다.
- Hermes나 MCP는 별도 이메일 저장소나 첨부파일 보관소를 만들지 않는다.
